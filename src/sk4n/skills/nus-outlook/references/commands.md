# `nus-outlook` command reference

> Generated by `scripts/generate_skill_references.py` from the argparse tree. Do not edit manually.

Read and incrementally cache NUS Outlook mail and look up people using a saved NUS SSO browser login.

## Output formats

- Omit `--format` for concise human-readable tables or details.
- Use `--format json` for one complete JSON document.
- Use `--format jsonl` for one complete JSON record per line when the command offers it.
- Use `--format plain` for line-oriented `key: value` records suited to shell filtering when the command offers it.
- Structured formats preserve full records and may be substantially larger than human output.

## Commands

- `nus-outlook auth` — Manage the saved NUS login.
- `nus-outlook auth status` — Check the saved login.
- `nus-outlook auth login` — Open a browser for NUS login and MFA.
- `nus-outlook auth logout` — Delete this CLI's saved login without signing other browsers out.
- `nus-outlook folders` — List mailbox folders.
- `nus-outlook people` — Find people's email addresses in the NUS directory.
- `nus-outlook messages` — List messages without marking them read.
- `nus-outlook search` — Search mailbox messages.
- `nus-outlook message` — Read one message without changing its read state.
- `nus-outlook api` — Make a read-only Outlook web API request.
- `nus-outlook playwright-cli` — Open an authenticated @playwright/cli inspection session.

| Argument | Required | Repeatable | Default | Choices | Description |

| `-h, --help` | no | no | `—` | — | show this help message and exit |
| `PATH` | yes | no | `—` | — | Supported /owa/service.svc read action, /searchservice/api/v2/query (mail), or /search/api/v2/query (people) path. |
| `-X, --method METHOD` | no | no | `GET` | GET, POST | HTTP method. Default: GET. POST is limited to supported read actions. |
| `-d, --data JSON` | no | no | `—` | — | JSON request body. |

Constraints:

- Only /owa/service.svc with a supported read action, POST /searchservice/api/v2/query (mail), or POST /search/api/v2/query (people) is accepted; state-changing actions are rejected.
- Never use low-level APIs for writes, even with an explicit user request or approval. Use the browser UI for authorized writes.
